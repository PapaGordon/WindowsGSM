# MeFriendos WindowsGSM v1.25.4.3

## ATM10 update fix

Fixes a real 8.1 -> 8.3 update case where Better Compatibility Checker kept advertising 8.1 after the pack files changed. The pack-managed BCC identity now follows the selected original server ZIP, other local settings stay in place, and WGSM refreshes its installed-version success message after the update.

Additional custom mod JARs are preserved. The updater tracks official pack files with SHA-256 ownership records and removes obsolete files only when that record proves they belong to the old pack. Conflicting additional files or duplicate actual mod IDs stop the update before activation.

**Important for the first update from an older plugin:** keep the previous original `ServerFiles-<installed-version>.zip` beside the new ZIP. Without an existing ownership inventory or that old original ZIP, the updater refuses to guess which mods are yours. Do not make the old ZIP from your modified server folder. World backups remain recommended.

The ATM10 entry now uses its native logo. DayZ keeps the native game image.

The built-in account-based servers and our standalone plugins use WGSM's central SteamCMD login, so the encrypted password added in v1.25.4.2 works with Arma 3, DayZ and Farming Simulator 22/25. Anonymous SteamCMD downloads stay anonymous. Minecraft, NeoForge and ATM10 do not use a Steam password.

- Fixes the older DayZAuto SDK example, which still read only the plaintext password. The updated source uses the shared reader and cancels its download if credentials cannot be read.
- Recognizes both `Minecraft_NeoForge.cs` and the earlier `NeoForge.cs` server identifier as the existing built-in entry.
- Adds compile and encrypted-login checks covering all current standalone MeFriendos plugins and their built-in counterparts.

## Standalone NeoForge

[WindowsGSM.Minecraft_NeoForge](https://github.com/PapaGordon/WindowsGSM.Minecraft_NeoForge/releases/latest) is available for compatible WGSM hosts that do not use our fork. It includes its own runtime helpers, the official fox icon, the same version selection and the same staged-update behavior. ATM10 is not required. Our fork already includes this server, so there is no need to install the standalone plugin here.

The existing plugin READMEs now link the current MeFriendos release and explain which servers need account login. Their separate patch releases keep their server runtime behavior unchanged.

## Update and encrypted password setup

Quit WGSM, back up your installation and replace the EXE. Keep your server, plugin and configuration folders. The ZIP includes the same password helper as v1.25.4.2; an already encrypted password does not need converting again.

To encrypt a password for the first time, extract the ZIP into your WGSM directory and run **Encrypt-SteamPassword.cmd** as the same Windows user that runs WGSM. Enter your Steam login name and password at the hidden prompt. The helper removes the readable password from `bin/steamcmd/userData.txt` and saves the encrypted value. It does not create a plaintext backup or sign into Steam.

[Password instructions and limits](https://github.com/PapaGordon/WindowsGSM/blob/v1.25.4.3/STEAM-CREDENTIALS.md). Encryption protects the saved file; privileged processes can still read SteamCMD's decrypted process arguments. Steam Guard may need confirmation. The built-in DayZ module still does not automatically update Workshop mods.

## Validation

Checked with plugin compilation, synthetic encrypted credentials, local configuration/update fixtures, an isolated official NeoForge installer run and the packed EXE's startup/plugin loader. These checks do not verify live multiplayer, a real Steam login or every third-party WGSM fork.
